## 비밀번호 관리자 4종 6개월 실사용 비교: 1Password·Bitwarden·Proton Pass·iCloud 키체인

비밀번호 관리자는 한 번 도입하면 마이그레이션 비용이 매우 큽니다. 데이터 이관 자체가 귀찮을 뿐만 아니라, 가족 공유나 자동 입력 패턴에 온가족이나 팀 전체의 습관이 적응해 버리기 때문입니다. 저 역시 크롬 기본 저장 기능에서 시작해 여러 서비스를 전전하다가, 결국 대표적인 비밀번호 관리자 4종(1Password, Bitwarden, Proton Pass, iCloud 키체인)을 각각 최소 6개월 이상 주력으로 결제하여 사용해 보았습니다.

새로운 관리자를 선택할 때 단순 기능 목록보다 중요한 것은 보안 모델의 구조적 차이, 패스키(Passkey) 전환기 지원 수준, 그리고 가족 단위 공유의 편리함입니다. 이번 글에서는 4개 서비스의 실사용 경험을 바탕으로 나에게 맞는 최적의 보안 환경을 구축하는 방법을 정리해 드립니다.

## 지금 비밀번호 관리자를 전환해야 하는 이유

보안 사고의 상당수는 서비스 자체의 해킹보다는 '계정 재사용'에서 발생합니다. 특정 웹사이트의 DB가 유출되었을 때, 동일한 아이디와 비밀번호를 쓰는 다른 중요 사이트(이메일, 금융, 쇼핑몰 등)로 해커가 로그인 공격을 시도하는 크리덴셜 스터핑(Credential Stuffing) 위험에 노출되기 때문입니다.

또한, 비밀번호 자체를 없애는 기술인 패스키(Passkey) 호환성이 본격화되면서, 향후 로그인 생태계의 주도권을 어떤 관리자가 쥐게 될지도 중요해졌습니다. 여기에 더해 가족이나 팀원 간에 와이파이 비밀번호, OTT 계정, 가계부 공유 계정을 관리하는 방식이 서비스마다 크게 달라 초기 선택이 향후 몇 년간의 생산성을 좌우합니다.

## 이관 전 준비해야 할 3가지

비밀번호 관리자 이관을 시작하기 전, 다음 세 가지 요소를 미리 확인하면 진행 과정에서 생기는 혼선을 크게 줄일 수 있습니다.

1. **기존 브라우저/기기의 데이터 내보내기 권한:** 크롬, 사파리, 엣지 등에 저장된 계정 정보를 CSV 파일로 내보낼 수 있는지 확인합니다.
2. **주 사용 기기 및 OS 환경:** 맥북과 윈도우 데스크톱, 아이폰과 안드로이드 태블릿처럼 이종 기기가 섞여 있는지 점검합니다.
3. **공유가 필요한 계정의 범위:** 혼자만 쓸 것인지, 배우자나 가족과 함께 공용 금고(Vault)를 운영할 것인지 결정합니다.

## 단계별 이관 및 세팅 가이드

### 1단계: 흩어진 자격 증명 한곳으로 모으기

가장 먼저 할 일은 크롬(`chrome://password-manager/settings`), 사파리, 엣지 등에 흩어진 자격 증명을 CSV 파일 형태로 추출하는 것입니다. 추출된 파일 내에서 중복된 계정과 이미 사용하지 않는 서비스의 데이터를 정리합니다. 이 과정에서 동일한 비밀번호가 몇 개 사이트에 재사용되고 있는지 눈으로 확인하면 정리의 우선순위가 명확해집니다.

> **팁:** 추출된 CSV 파일은 암호화되지 않은 순수 평문(Plaintext)입니다. 비밀번호 관리자로 가져오기(Import)를 마친 즉시 해당 파일은 휴지통 비우기뿐만 아니라 완전 삭제(Shred) 처리를 해야 안전합니다.

### 2단계: 보안 모델 기준으로 후보 좁히기

각 서비스는 보안을 구현하는 철학에 차이가 있습니다.

* **1Password:** 마스터 비밀번호 외에 12자리 알파벳·숫자로 구성된 '비밀 키(Secret Key)'를 기기 등록 시 추가로 요구합니다. 1Password 서버가 해킹당하더라도 비밀 키 없이는 암호문 해독이 불가능한 수준의 추가 보호막을 제공합니다.
* **Bitwarden:** 소스 코드가 완전히 공개된 오픈소스(Open-source) 기반입니다. 외부 보안 감사를 주기적으로 받으며, 보안에 민감한 사용자라면 자신의 개인 서버에 직접 구축(Self-host)할 수 있습니다.
* **Proton Pass:** 스위스 프라이버시 법의 보호를 받는 서비스로, 가짜 이메일 주소를 생성해 주는 '이메일 별칭(Hide-my-email)' 기능이 기본 탑재되어 본래 이메일 주소 유출을 방지합니다.
* **iCloud 키체인:** 애플 생태계 내에서 종단간 암호화(End-to-End Encryption)로 가장 매끄럽게 작동하며 별도의 구독료가 들지 않습니다.

> **팁:** 어떤 서비스를 선택하든 마스터 비밀번호는 기억하기 쉬우면서도 추측하기 어려운 무작위 단어 4개 이상의 조합(예: `apple-piano-river-cloud`)으로 생성하고, 반드시 종이에 직접 적어 오프라인에 보관하세요.

### 3단계: 패스키 및 2차 인증(TOTP) 저장 정책 수립

로그인 보안을 강화하기 위해 패스키 지원 여부와 2차 인증(TOTP) 분리 여부를 결정해야 합니다. 패스키를 비밀번호 관리자에 저장하면 맥북에서 만든 패스키를 윈도우나 안드로이드 기기에서도 바로 사용할 수 있어 확장성이 뛰어납니다. 

다만, 2단계 인증 번호(OTP) 생성기까지 모두 하나의 비밀번호 관리자 금고 안에 넣어두면, 마스터 비밀번호 하나가 뚫렸을 때 모든 2차 인증까지 함께 무너지는 단일 실패 지점(Single Point of Failure)이 발생합니다. 따라서 금융 기관이나 핵심 이메일 계정의 TOTP는 별도의 OTP 앱(Google Authenticator, YubiKey 등)으로 분리하는 정책을 추천합니다.

> **팁:** 서비스 가입 시 발급되는 '비상 복구 코드(Recovery Code)'는 비밀번호 관리자 내부 노트가 아닌, 물리적 메모지나 오프라인 외장 매체에 따로 보관하는 것이 안전합니다.

### 4단계: 공유 금고 구성 및 브라우저 자체 저장 비활성화

서비스 선택 후 개인 금고(Personal Vault)와 공유 금고(Shared Vault)를 명확히 분리합니다. 인터넷 요금제, 와이파이 접속 정보, OTT 구독 계정 등은 공유 금고에 넣고 배우자나 가족을 초청합니다. 

이관 작업이 끝났다면 기존에 사용하던 웹 브라우저의 자체 비밀번호 저장 및 자동 완성 기능은 반드시 끔(`Off`) 상태로 변경해야 합니다. 두 곳 모두에서 자동 완성이 작동하면 새로 변경된 비밀번호가 브라우저에는 업데이트되지 않아 추후 데이터 불일치 문제가 발생합니다.

> **팁:** 비밀번호 관리자 이관 완료 후 첫 한 달 동안은 자주 방문하는 주요 계정 20개의 비밀번호를 관리자의 '무작위 생성기(최소 16자리 이상, 특수문자 포함)'를 통해 새롭게 교체하는 작업을 진행하세요.

## 6개월 실사용에서 얻은 핵심 팁

> **생태계에 따른 선택 기준:** 애플 기기만 사용하는 순수 Apple 생태계 사용자라면 iCloud 키체인으로 시작해도 기능적으로 부족함이 없습니다. 그러나 윈도우 데스크톱이나 안드로이드 공기계가 하나라도 섞이는 순간, Cross-Platform 지원이 완벽한 1Password나 Bitwarden으로 넘어가는 편이 스트레스를 줄이는 길입니다.

> **이메일 별칭 활용:** Proton Pass나 1Password(Fastmail 연동)에서 제공하는 이메일 별칭 기능을 활용하면, 신규 웹사이트 가입 시 무작위 이메일 주소를 생성해 가입할 수 있습니다. 추후 특정 서비스에서 스팸이 오거나 데이터가 유출되었을 때 어느 경로에서 유출되었는지 즉시 역추적하고 해당 별칭만 차단할 수 있습니다.

> **가족 요금제의 가성비:** 1Password나 Bitwarden의 가족 요금제(Family Plan)는 개인 요금제 대비 약 1.5배의 가격으로 최대 5～6명까지 공유 금고를 사용할 수 있습니다. 가족 구성원이 2명 이상이라면 개인 플랜을 각각 결제하는 것보다 가족 플랜을 구성하는 것이 비용 및 계정 관리 면에서 월등히 유리합니다.

## 한 걸음 더 — 디지털 유산과 비상 접근 계획

비밀번호 관리자를 제대로 활용하여 모든 계정을 강력한 무작위 비밀번호로 바꾸고 나면, 역설적으로 새로운 위험 요소가 등장합니다. 본인이 불의의 사고를 당했을 때, 본인만 접근할 수 있는 암호화 금고 안에 남아있는 가족의 삶에 필요한 정보(은행 계좌, 보험, 공과금, 가족 사진 저장소 등)까지 완전히 격리되어 버린다는 점입니다.

이를 방지하기 위해 1Password와 Bitwarden은 '비상 접근(Emergency Access)' 기능을 제공합니다. 신뢰할 수 있는 보호자(예: 배우자, 부모, 자녀)의 계정을 비상 연락처로 지정해 두고, 그 사람이 내 금고 접근 권한을 요청했을 때 지정된 대기 시간(예: 7일) 동안 본인이 승인을 거절하지 않으면 자동으로 금고 열람 권한이 부여되는 구조입니다. 대기 시간을 며칠 이상으로 길게 설정해 두면 평소의 오남용 위험은 방지하면서 물리적 부재 상황에 대비할 수 있습니다.

비상 접근 기능을 지원하지 않거나 오프라인 중심의 관리를 선호한다면 '봉인된 비상 키트' 방식이 대안입니다. 마스터 비밀번호와 계정 복구 키, 2차 인증 백업 코드를 종이에 인쇄한 후 봉투에 넣어 양초 농으로 봉인하거나 열 수 없는 구조로 만든 뒤 신뢰할 수 있는 가족이나 변호사, 물리적 개인 금고에 보관합니다. 핵심은 이 비상 봉투의 존재와 보관 장소를 가족 중 최소 한 명은 알고 있어야 한다는 점입니다. 완벽하게 숨겨진 백업은 위기 상황에서 존재하지 않는 것과 같습니다. 1년에 한 번 캘린더 알림을 맞춰두고 비상 키트의 유효성을 점검하는 습관이 필요합니다.

또한, 마이그레이션을 마친 후에는 각 관리자가 제공하는 '유출 모니터링(Watchtower 또는 Vault Health)' 기능을 켜둘 것을 권장합니다. 기존에 알려진 해킹 데이터베이스와 내 금고 속 계정을 주기적으로 대조하여 유출된 비밀번호, 2단계 인증 미설정 계정, 중복 사용 중인 암호를 선제적으로 알려줍니다. 경고가 발생할 때마다 해당 사이트에 접속해 비밀번호를 하나씩 바꿔나가는 분기별 점검을 루틴화하면 사고가 터지더라도 피해 범위를 단 하나의 계정으로 제한할 수 있습니다.

## 자주 묻는 질문 (FAQ)

**Q1. 마스터 비밀번호를 잊어버리면 정말로 찾을 수 없나요?**  
네, 그렇습니다. 본 비교에서 다룬 비밀번호 관리자들은 모두 사용자 측에서 암호화가 이루어지는 '영지식(Zero-Knowledge)' 보안 구조를 채택하고 있습니다. 서비스 개발사나 서버 관리자조차 사용자의 마스터 비밀번호나 금고 내부 평문 데이터를 알 수 없습니다. 따라서 비밀번호를 잊어버렸을 경우, 초기 가입 시 별도로 인쇄하거나 저장해 둔 '복구 키(Recovery Key)'나 '비상 키트(Emergency Kit)'가 없다면 계정 내부 데이터는 영구적으로 복구할 수 없습니다.

**Q2. 크롬이나 사파리 같은 브라우저 기본 저장 기능만 쓰면 안 되나요?**  
단 하나의 브라우저와 단 하나의 OS만 사용하는 환경이라면 기본 기능도 훌륭한 역할을 합니다. 하지만 모바일 앱 자동 입력의 정교함, 이종 OS 간의 완벽한 동기화, 가족 간의 안전한 암호 공유 금고 기능, 유출 모니터링 기능, 그리고 패스키의 이식성 면에서 전용 비밀번호 관리자가 제공하는 보안성과 편의성이 훨씬 뛰어납니다.

**Q3. Bitwarden 같은 오픈소스를 개인 서버에 자체 호스팅(Self-host)하는 것이 더 안전한가요?**  
네트워크 보안 및 서버 OS 보안 패치, 24시간 백업 체계를 직접 완벽하게 관리할 능력이 있는 전술적 엔지니어가 아니라면 상용 클라우드 플랜을 쓰는 것이 훨씬 안전합니다. 보안 패치를 놓치거나 백업 없이 운영하다가 데이터가 날아간 개인 서버는 전문 보안 팀이 24시간 가동되는 상용 서비스 서버보다 훨씬 취약합니다.

비밀번호 관리자를 고를 때 절대적으로 완벽한 단 하나의 정답은 없습니다. 애플 생태계에 몰입되어 있다면 **iCloud 키체인**으로 시작해도 좋고, 가성비와 기술적 자유도를 원한다면 **Bitwarden**, 프라이버시와 이메일 보호가 우선이라면 **Proton Pass**, 그리고 돈을 조금 내더라도 최상의 앱 완성도와 추가 보안 레이어를 경험하고 싶다면 **1Password**가 좋은 선택이 됩니다.
