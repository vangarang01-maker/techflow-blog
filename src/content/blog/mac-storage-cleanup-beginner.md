이 글은 같은 주제를 처음 접하는 분을 기준으로 다시 정리한 입문 버전입니다. 용어와 사전 준비부터 차근히 짚습니다.

"시스템 데이터 120GB"의 정체를 모른 채 청소 앱부터 설치하면 위험합니다. 안전한 순서대로, 효과 큰 것부터 지우는 방법을 정리했습니다.

**이 글에서 다루는 내용**

1. 무엇이 차지하는지 먼저 보기
2. Time Machine 로컬 스냅샷 정리하기
3. 개발 도구·앱 캐시 비우기
4. 대용량 파일과 중복 정리 후 규칙 만들기

## 왜 지금 정리해야 할까요

- SSD 여유 공간이 10% 아래로 내려가면 스왑과 쓰기 성능이 눈에 띄게 나빠집니다.
- 무분별한 청소 앱은 앱 설정과 라이선스 파일까지 지워 재설정 비용을 만듭니다.
- 용량을 차지하는 항목은 대개 5개 이내라 원인만 찾으면 정리가 빨리 끝납니다.

## 시작 전 준비물

- Time Machine 또는 최신 백업 1회
- `Cmd + Space` → "저장 공간" 설정 화면
- 용량 시각화 도구(GrandPerspective, DaisyDisk 중 택1)

## 단계별 실행 가이드

### 1단계 — 무엇이 차지하는지 먼저 보기

시스템 설정 → 일반 → 저장 공간에서 항목별 용량을 확인하고, 시각화 도구로 폴더 단위 크기를 봅니다. 추측으로 지우기 시작하면 시간만 쓰고 용량은 거의 늘지 않습니다.

> **팁:** 시각화 도구는 전체 디스크 접근 권한을 줘야 정확한 결과가 나옵니다.

### 2단계 — Time Machine 로컬 스냅샷 정리하기

"시스템 데이터"가 비정상적으로 크다면 로컬 스냅샷이 원인인 경우가 많습니다. `tmutil listlocalsnapshots /`로 확인하고 오래된 것부터 `tmutil deletelocalsnapshots <날짜>`로 지웁니다.

> **팁:** 외장 백업이 최신이라면 로컬 스냅샷은 안전하게 삭제됩니다.

### 3단계 — 개발 도구·앱 캐시 비우기

Xcode의 DerivedData와 iOS 시뮬레이터, node_modules, 도커 이미지가 수십 GB를 차지하는 경우가 흔합니다. `~/Library/Developer/Xcode/DerivedData`, `docker system prune -a` 순으로 확인하세요.

> **팁:** `~/Library/Caches`는 앱별로 확인하고 통째로 지우지 마세요. 일부 앱은 재로그인을 요구합니다.

### 4단계 — 대용량 파일과 중복 정리 후 규칙 만들기

다운로드 폴더, 데스크톱, 메일 첨부 캐시를 확인하고 30일 이상 지난 파일을 아카이브합니다. 마지막으로 다운로드 폴더 자동 정리 규칙을 만들어 같은 상황이 반복되지 않게 합니다.

> **팁:** 사진 앱의 "원본 다운로드" 옵션을 "저장 공간 최적화"로 바꾸면 수십 GB가 회수됩니다.

## 용량 회수 효과와 위험도

| 항목 | 평균 회수량 | 위험도 |
| --- | --- | --- |
| 로컬 스냅샷 | 10~80GB | 낮음(백업 있을 때) |
| Xcode DerivedData | 5~40GB | 낮음 |
| 도커 이미지 | 10~60GB | 중간(재빌드 필요) |
| 시스템 라이브러리 임의 삭제 | 가변 | 높음 — 권장하지 않음 |

## 실전 프로 팁

- 외장 SSD에 프로젝트 아카이브 폴더를 만들고 분기마다 옮기면 내장 용량이 안정적으로 유지됩니다.
- 메시지 앱의 첨부 파일은 설정에서 "30일 후 삭제"로 바꾸면 자동 관리됩니다.
- 메일 앱은 첨부 파일을 로컬에 중복 보관합니다. 계정 설정에서 다운로드 정책을 확인하세요.

## 한 걸음 더 — 용량이 다시 차지 않게 만드는 규칙

한 번 정리하고 나면 대개 두세 달 뒤 같은 상태로 돌아옵니다. 유입을 관리하지 않았기 때문입니다. 가장 효과가 큰 규칙은 다운로드 폴더 자동 정리입니다. 단축어나 Hazel로 "30일 이상 열지 않은 파일은 아카이브 폴더로 이동"을 걸어두면 손대지 않아도 유지됩니다. 아카이브 폴더는 분기마다 한 번만 확인하고 통째로 비우면 됩니다.

두 번째는 프로젝트 종료 규칙입니다. 프로젝트가 끝나면 결과물만 남기고 중간 산출물, 렌더 캐시, 시안 파일은 외장 디스크로 옮깁니다. 이 작업을 프로젝트 종료 체크리스트에 넣어두면 잊지 않게 됩니다. 마지막으로 매달 1일에 저장 공간 화면을 여는 5분짜리 반복 일정을 걸어두세요. 문제를 조기에 발견하면 대청소가 필요 없어집니다.

용량 문제가 반복된다면 파일이 아니라 작업 방식을 볼 차례입니다. 영상 편집이나 대용량 데이터 작업을 한다면 내장 디스크를 작업 공간이 아니라 임시 공간으로만 쓰고, 프로젝트는 외장 SSD에 두는 구조가 훨씬 안정적입니다. 최근 Thunderbolt·USB4 외장 SSD는 속도 차이가 거의 없으며, 프로젝트 단위로 디스크를 분리하면 백업과 아카이브도 함께 단순해집니다.

## 자주 겪는 문제와 해결법

### Q. 지웠는데 용량이 그대로입니다.

**A.** 휴지통 비우기 후에도 스냅샷이 참조 중이면 즉시 반영되지 않습니다. 재부팅 후 몇 분 기다리면 정리됩니다.

### Q. 청소 앱을 써도 되나요?

**A.** 유명 앱이라도 시스템 영역을 건드리는 옵션은 끄는 편이 안전합니다. 용량 확인 용도로만 쓰고 삭제는 직접 판단하세요.

### Q. 용량이 항상 부족하다면?

**A.** 외장 SSD를 상시 연결해 프로젝트 작업 폴더를 옮기는 편이 근본 해결입니다. 최근 외장 NVMe는 내장과 체감 차이가 크지 않습니다.
