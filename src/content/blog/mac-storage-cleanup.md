## 맥 저장 공간 되찾기: 안전하게 지워도 되는 것과 아닌 것

"시스템 데이터 120GB"라는 붉은색 막대를 마주했을 때, 당황해서 서드파티 청소 앱부터 설치하고 실행하는 분들이 많습니다. 하지만 정체를 알 수 없는 시스템 데이터를 무작정 청소 프로그램으로 지우려 하면 앱 실행 라이선스가 날아가거나, 주요 앱의 환경설정이 초기화되어 수습하는 데 더 많은 시간이 들곤 합니다.

macOS의 저장 공간을 정리할 때는 안전한 순서대로, 효과가 가장 큰 항목부터 차근차근 확인하는 것이 정석입니다. 왜 용량 관리가 필요한지, 그리고 삭제 전 무엇을 준비해야 하는지부터 알아본 뒤 실행에 들어가겠습니다.

### 왜 저장 공간 정리와 순서가 중요한가?

맥의 NVMe SSD는 여유 공간이 전체 용량의 10% 미만으로 떨어지면 성능이 눈에 띄게 저하됩니다. macOS는 메모리가 부족할 때 SSD의 일부를 가상 메모리(Swap)로 전환해 사용하는데, 남은 용량이 턱없이 부족하면 쓰기 속도가 떨어지고 시스템 전체에 렉이 발생합니다.

* **성능 저하의 주원인:** SSD 여유 공간 부족으로 인한 스왑 메모리 병목 및 쓰기 성능 하락.
* **무분별한 청소 앱의 위험성:** 샌드박스 영역을 무시하고 삭제하는 청소 앱은 앱 라이선스 인증 파일과 캐시를 구분하지 못해 재설정 비용을 유발합니다.
* **효율적인 접근법:** 실제로 용량을 대량으로 점유하는 항목은 보통 5개 이내입니다. 원인을 시각적으로 정확히 파악하면 몇 분 만에 수십 GB를 회수할 수 있습니다.

### 정리 전 필수 준비 사항

본격적으로 파일이나 스냅샷을 삭제하기 전에 반드시 아래 3가지를 준비하세요.

1. **Time Machine 또는 외장 드라이브 백업:** 중요 파일이 실수로 지워지는 상황을 방지하기 위해 최신 백업을 1회 실행합니다.
2. **저장 공간 설정 화면 열기:** `Cmd + Space`를 눌러 스포트라이트를 연 뒤, "저장 공간"을 입력하여 `시스템 설정 → 일반 → 저장 공간` 경로로 이동합니다.
3. **용량 시각화 도구 준비:** 맥 앱스토어나 공식 웹사이트에서 `GrandPerspective` 또는 `DaisyDisk` 중 하나를 설치합니다.

## 4단계로 끝내는 안전한 저장 공간 정리

### 1단계: 무엇이 용량을 차지하는지 시각화로 먼저 파악하기

추측으로 다운로드 폴더나 문서 폴더만 뒤적거리면 시간만 소비하고 정작 용량은 거의 늘지 않습니다. macOS 설정의 저장 공간 탭에서 대략적인 범주를 확인한 후, 용량 시각화 도구를 활용해야 합니다.

* **실행 경로:** `시스템 설정 → 일반 → 저장 공간`
* **시각화 앱 활용:** GrandPerspective나 DaisyDisk를 실행해 시스템 디스크를 스캔합니다.

> **Tip: 시각화 도구 권한 설정**  
> 시각화 도구가 디스크의 모든 폴더 크기를 정확하게 측정하려면 전체 디스크 접근 권한이 필요합니다. `시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근 권한`에서 사용 중인 시각화 앱을 활성화한 후 스캔하세요.

### 2단계: Time Machine 로컬 스냅샷 정리하기

"시스템 데이터" 항목이 50GB～100GB 이상으로 비정상적으로 크다면 십중팔구 Time Machine의 '로컬 스냅샷(Local Snapshots)'이 원인입니다. 외장 백업 디스크가 연결되지 않은 동안에도 macOS는 백업을 위해 내부 SSD에 변경사항을 스냅샷으로 저장합니다.

스냅샷은 원래 공간이 부족하면 자동으로 삭제되도록 설계되어 있지만, 간혹 시스템 오류로 삭제되지 않고 쌓이는 경우가 발생합니다. 터미널을 이용해 안전하게 제거할 수 있습니다.

1. `Cmd + Space`로 **터미널(Terminal)**을 실행합니다.
2. 현재 생성된 로컬 스냅샷 목록을 확인합니다.
   ```bash
   tmutil listlocalsnapshots /
   ```
3. 날짜별로 표시된 스냅샷 중 오래된 항목을 삭제합니다.
   ```bash
   sudo tmutil deletelocalsnapshots 2024-03-15-101234
   ```
   *(비밀번호 입력 요청 시 맥 계정 비밀번호를 입력합니다. 화면에 글자가 보이지 않아도 정상적으로 입력되고 있는 것입니다.)*

> **Tip: 로컬 스냅샷 삭제의 안전성**  
> 최근 외장 디스크나 클라우드에 백업이 완료된 상태라면, 내부에 남은 로컬 스냅샷은 삭제해도 개별 데이터에 아무런 영향을 주지 않습니다.

### 3단계: 개발 도구 및 앱 캐시 비우기

개발자나 디자이너, 영상 편집자의 맥에는 작업 관련 찌꺼기 파일이 수십 GB씩 축적됩니다. 대표적으로 Xcode의 빌드 파일, iOS 시뮬레이터 잔여물, Docker 이미지, Node.js의 `node_modules` 폴더가 있습니다.

#### Xcode DerivedData 삭제
Xcode로 앱을 빌드할 때 생성되는 임시 파일인 `DerivedData`는 지워도 프로젝트 재빌드 시 다시 생성되므로 안전합니다.
* **삭제 경로:** `~/Library/Developer/Xcode/DerivedData`
* 파인더(Finder)에서 `Cmd + Shift + G`를 누른 후 위 경로를 입력해 이동한 뒤 폴더 내부 항목을 전체 삭제하세요.

#### Docker 쓰레기 정리
Docker를 사용하는 개발자라면 미사용 컨테이너와 빌드 캐시가 디스크를 대량 점유합니다. 터미널에 아래 명령어를 입력하여 한 번에 정리합니다.
```bash
docker system prune -a --volumes
```
이 명령어는 중지된 컨테이너, 사용되지 않는 네트워크, 사용되지 않는 이미지 및 볼륨을 한 번에 정리하여 보통 10～50GB 이상의 용량을 되찾아 줍니다.

#### 앱 캐시(`~/Library/Caches`) 관리 주의사항
파인더에서 `~/Library/Caches` 경로로 이동하면 다양한 앱의 캐시 파일이 존재합니다.
* **주의:** `Caches` 폴더 전체를 통째로 지우지 마세요.
* 메신저 앱(카카오톡, 슬랙)이나 브라우저, Adobe 제품군 등 특정 앱 폴더 내부의 데이터만 선별하여 지워야 합니다. 폴더 전체를 지우면 앱 설정 값이 날아가거나 다시 로그인해야 하는 번거로움이 발생합니다.

### 4단계: 대용량 파일 정리 및 자동 관리 규칙 적용

마지막 단계는 다운로드 폴더, 데스크톱, 메일 첨부 파일 정리입니다.

1. **다운로드 폴더 정리:** 설치용 `.dmg` 파일, 압축 해제 후 남은 `.zip` 파일은 즉시 지웁니다.
2. **사진 앱 용량 최적화:**  
   `사진 앱 실행 → 설정 → iCloud`로 이동하여 ‘**Mac 저장 공간 최적화**’를 선택합니다. 원본 사진은 iCloud에 보관되고 맥에는 용량이 작은 썸네일 위주로 저장되어 20～80GB 이상의 공간을 즉시 확보할 수 있습니다.
3. **메시지 및 메일 첨부 파일:**  
   `시스템 설정 → 일반 → 저장 공간 → 문서(또는 메시지)` 항목 옆의 'i' 아이콘을 클릭하면 대용량 파일과 다운로드된 첨부 파일을 목록 형태로 확인하여 선택 삭제할 수 있습니다.

## 용량 회수 효과 및 위험도 비교

정리 작업별 회수 가능한 평균 용량과 삭제 시 위험도를 정리한 표입니다. 작업 우선순위를 정할 때 참고하세요.

| 항목 | 평균 회수량 | 위험도 | 비고 |
| :--- | :--- | :--- | :--- |
| **로컬 스냅샷 (tmutil)** | 10～80GB | **낮음** (백업 존재 시) | 시스템 데이터의 비정상적 증가 시 최우선 정리 대상 |
| **Xcode DerivedData** | 5～40GB | **낮음** | 삭제 후 첫 빌드 시 시간 약간 소요 |
| **Docker 이미지/볼륨** | 10～60GB | **중간** (재빌드 필요) | 컨테이너 재작성 및 데이터베이스 재구축 필요 여부 확인 |
| **사진 앱 저장 공간 최적화** | 20～100GB | **낮음** | 인터넷 연결 시 원본 언제든 재다운로드 가능 |
| **`~/Library` 시스템 폴더 임의 삭제** | 가변 | **높음 (권장하지 않음)** | OS 부팅 불능 및 앱 환경설정 유실 위험 |

## 작업 효율을 높이는 실전 유지관리 팁

* **외장 SSD 기반의 아카이브 라이브러리 운용:**  
  완료된 프로젝트 폴더나 자주 열지 않는 대용량 미디어 파일은 맥 내부에 두지 말고, 외장 SSD에 `Archive_연도` 폴더를 만들어 분기마다 이관하세요. 내장 SSD는 현재 진행 중인 작업 전용으로만 사용하는 것이 좋습니다.

* **메시지 앱 첨부 파일 자동 삭제 설정:**  
  `메시지 앱 → 설정 → 일반 → 메시지 보관 기간` 옵션을 '영구히'에서 ‘**30일**’ 또는 ‘**1년**’으로 변경하세요. 음성 메시지와 고화질 동영상 첨부 파일이 자동으로 정리됩니다.

* **메일(Mail) 앱 첨부 파일 관리:**  
  macOS 기본 메일 앱은 메일에 포함된 문서와 이미지를 로컬 SSD에 중복 보관합니다. `메일 앱 → 설정 → 계정 → 계정 정보`에서 첨부 파일 다운로드 옵션을 '최근 항목' 또는 '없음'으로 조정하면 원인 모를 저장 공간 점유를 줄일 수 있습니다.

## 한 걸음 더 — 용량이 다시 차지 않게 만드는 규칙

한 번 대청소를 진행해 용량을 확보하더라도 두세 달이 지나면 다시 저장 공간 부족 알림이 뜨는 경우가 많습니다. 이는 파일이 유입되고 쌓이는 구조적인 규칙을 만들어두지 않았기 때문입니다.

첫 번째로 가장 효과적인 방법은 **다운로드 폴더의 자동화 규칙**입니다. macOS의 기본 '단축어' 앱이나 'Hazel' 같은 자동화 유틸리티를 활용해 "생성된 지 30일이 지난 파일 중 열어보지 않은 파일은 Archive 폴더로 자동 이동"하도록 조건문 규칙을 걸어두세요. 이렇게 하면 다운로드 폴더에 쌓인 dmg 설치 파일이나 임시 다운로드 문서들이 알아서 정리됩니다. Archive 폴더는 3개월에 한 번씩만 확인한 후 통째로 비우면 끝납니다.

두 번째는 **프로젝트 종료 체크리스트**를 만드는 것입니다. 디자인, 영상, 개발 등 작업이 완료되면 프로젝트를 종료할 때 다음 작업을 절차화합니다.
1. 중간 렌더링 캐시 및 빌드 파일 삭제
2. 최종 결과물 파일만 아카이브 드라이브로 복사
3. 작업 디렉토리 내 임시 시안 파일 삭제

마지막으로 매달 1일을 ‘**저장 공간 점검의 날**’로 지정하고 구글 달력이나 Apple 미리 알림에 5분짜리 반복 일정을 등록해 두세요. `시스템 설정 → 저장 공간` 탭을 열어 5분간 점검하는 습관만 들여도 대대적인 청소를 할 필요 없이 항시 20% 이상의 여유 공간을 안정적으로 유지할 수 있습니다.

만약 대용량 4K 영상 편집이나 딥러닝 데이터셋 다루기 등 작업 특성상 용량 부족이 끊임없이 반복된다면, 파일 삭제 노력보다는 **작업 환경 구조의 개편**이 필요합니다. 최근 출시되는 Thunderbolt 4 및 USB4 기반의 외장 NVMe SSD는 읽기/쓰기 속도가 2,800MB/s 이상으로 내장 SSD와 체감 성능 차이가 거의 없습니다. 프로젝트 작업 공간 자체를 외장 SSD로 드라이브 매핑하여 사용하는 것이 근본적인 해결책입니다.

## 자주 겪는 문제 해결 (FAQ)

**Q1. 파일과 캐시를 지웠는데도 저장 공간 용량이 그대로입니다.**  
A1. 휴지통을 비운 후에도 macOS의 APFS 파일 시스템 특성상 스냅샷이 해당 파일의 이전 상태를 참조하고 있으면 용량이 즉시 반환되지 않습니다. 맥을 한 번 재부팅한 뒤 5～10분 정도 기다리면 시스템 데이터 점유량이 정상적으로 줄어든 것을 확인할 수 있습니다.

**Q2. CleanMyMac 같은 올인원 청소 앱을 써도 괜찮을까요?**  
A2. 용량 시각화나 단축키 정리 기능용으로 사용하는 것은 편리하지만, '원클릭 자동 청소' 기능으로 시스템 영역이나 딥 라이브러리 영역까지 지우는 것은 권장하지 않습니다. 수동 검토 옵션을 켜고 어떤 파일이 지워지는지 직접 확인한 후 삭제 버튼을 누르는 것이 안전합니다.

**Q3. 256GB 기본 용량 맥을 쓰고 있는데 항상 용량이 모자랍니다.**  
A3. 256GB 모델의 경우 macOS 시스템과 기본 캐시만으로도 약 40～50GB를 차지하므로 실제 사용 영역은 매우 제한적입니다. 이 경우 시스템 내부 정리는 최소화하고, 외부 NVMe SSD(1TB～2TB)를 상시 연결하여 `Downloads`, `Documents`, `Developer` 등의 주요 작업 폴더 자체를 외장 디스크로 심볼릭 링크(Symbolic Link)를 걸어 사용하는 방식을 강력히 추천합니다.
