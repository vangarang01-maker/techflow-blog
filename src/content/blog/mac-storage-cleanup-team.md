## 맥 저장 공간 되찾기, 안전하게 지워도 되는 것과 아닌 것 — 팀에 도입할 때의 체크포인트

인터넷에 널린 '맥 용량 늘리는 법' 블로그 글 10개를 그대로 따라 하다가 터미널 명령어 한 줄을 잘못 입력해 개발 환경이 통째로 꼬이고, 결국 맥을 초기화해야 했던 뼈아픈 경험이 있으신가요? 저 역시 몇 년 전, 정체불명의 '시스템 데이터' 150GB를 지우겠다고 온갖 서드파티 청소 앱을 깔았다가 유료 소프트웨어의 라이선스 인증 파일까지 함께 날려 먹고 사흘간 업무가 마비되는 삽질을 겪었습니다. 온갖 시행착오 끝에 깨달은 것은, 맥 저장 공간 관리는 무분별한 삭제가 아니라 '정밀한 타격'이 핵심이라는 점입니다.

오늘 소개할 방법은 프로덕션 환경에서 아무런 중단 없이, 안전하게 수십에서 수백 GB의 용량을 확보할 수 있는 검증된 최소 세팅 가이드입니다. 특히 개인의 세팅을 팀 단위로 확장할 때는 단순한 팁 공유를 넘어 합의와 문서화가 추가로 필요합니다. 도입 과정에서 실제로 팀원들이 가장 많이 헤매고 걸려 넘어졌던 실전 지점 위주로 다시 정리했습니다. '시스템 데이터 120GB'의 정체를 모른 채 무작정 청소 앱부터 실행하는 것은 매우 위험합니다. 가장 안전한 순서대로, 그리고 가장 효과가 큰 순서대로 맥의 숨은 용량을 회수해 보겠습니다.

## 왜 지금 당장 저장 공간을 정리해야 하는가?

맥의 저장 공간이 부족해지면 단순히 파일을 더 저장하지 못하는 것에 그치지 않습니다. 실무자 관점에서 반드시 용량을 확보해야 하는 실질적인 이유는 다음과 같습니다.

*   **스왑 메모리와 쓰기 성능 저하:** macOS는 RAM이 부족할 때 SSD의 일부를 가상 메모리(Swap)로 사용합니다. SSD의 여유 공간이 전체 용량의 10% 아래로 내려가면, 쓰기 성능이 눈에 띄게 나빠지며 시스템 전체가 버벅거리기 시작합니다.
*   **무분별한 청소 앱의 위험성:** 시중의 자동 청소 앱들은 앱 설정 파일(`.plist`)이나 라이선스 인증 파일까지 캐시로 오인해 지워버리곤 합니다. 이는 결국 도구를 재설정하고 환경을 다시 구축하는 데 수 시간의 보이지 않는 비용을 발생시킵니다.
*   **용량 낭비의 범인은 단 5개 이내:** 실제로 맥 용량을 많이 차지하는 항목은 대개 대용량 캐시, 로컬 스냅샷, 개발 도구 잔여물 등 5개 이내로 압축됩니다. 원인만 정확히 짚어내면 10분 만에 정리가 끝납니다.

## 준비 단계: 안전장치 마련과 도구 세팅

본격적인 삭제에 들어가기 앞서, 시스템을 안전하게 보호하고 용량을 시각적으로 파악할 준비를 해야 합니다. 딱 3가지만 준비하세요.

1.  **Time Machine 또는 최신 백업 1회 실행:** 혹시 모를 오작동에 대비해 외장 하드나 클라우드에 현재 상태를 백업합니다.
2.  **저장 공간 설정 화면 열기:** 단축키 `Cmd + Space`를 눌러 스포트라이트를 켠 뒤, "저장 공간"을 입력해 시스템 설정의 저장 공간 화면을 띄웁니다.
3.  **용량 시각화 도구 준비:** 추측만으로 폴더를 뒤지는 것은 시간 낭비입니다. 디스크 내부를 시각적으로 보여주는 **GrandPerspective**(무료) 또는 **DaisyDisk**(유료) 중 하나를 설치합니다.

> 💡 **팁:** 시각화 도구를 실행할 때는 반드시 맥의 `시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근 권한`에서 해당 앱을 허용해 주어야 시스템 영역까지 정확하게 스캔할 수 있습니다.

## 실전 4단계 저장 공간 회수 프로토콜

### 1단계: 무엇이 차지하는지 먼저 보기
시스템 설정의 `일반 → 저장 공간`으로 이동해 카테고리별 용량을 확인합니다. 여기서 '시스템 데이터'나 '개발자' 영역이 수십 GB 이상을 차지하고 있다면, 아래 단계들을 차례로 수행해야 합니다. 시각화 도구를 켜고 어떤 폴더가 비정상적으로 비대해졌는지 육안으로 먼저 확인하세요.

### 2단계: Time Machine 로컬 스냅샷 정리하기
외장 하드를 연결하지 않은 상태에서 Time Machine 백업이 활성화되어 있으면, macOS는 변경 사항을 맥 내부 SSD에 '로컬 스냅샷' 형태로 임시 저장합니다. 이 영역이 비대해지면 시스템 데이터 용량이 기하급수적으로 늘어납니다.

터미널(Terminal) 앱을 열고 아래 명령어를 입력해 현재 저장된 로컬 스냅샷 목록을 확인합니다.

```bash
tmutil listlocalsnapshots /
```

만약 목록에 여러 개의 스냅샷이 나타난다면, 아래 명령어로 오래된 스냅샷을 안전하게 삭제할 수 있습니다. (날짜 부분에 위 목록에서 확인한 값을 넣습니다.)

```bash
tmutil deletelocalsnapshots 2023-10-24-123456
```

> 💡 **팁:** 외장 백업 드라이브가 최신 상태로 연결되어 있다면, 로컬 스냅샷은 삭제해도 시스템에 아무런 해를 끼치지 않고 안전하게 용량만 회수됩니다.

### 3단계: 개발 도구 및 앱 캐시 비우기
개발자나 디자이너의 맥에서 가장 많은 용량을 차지하는 주범은 Xcode와 Docker, 그리고 Node.js의 잔여물입니다.

*   **Xcode DerivedData 정리:** Xcode가 빌드 시 생성하는 임시 파일들입니다. 프로젝트가 많을수록 수십 GB까지 불어납니다. 아래 경로로 이동해 폴더 안의 내용을 통째로 삭제하세요. 안전하게 자동 재생성되는 파일들입니다.
    *   경로: `~/Library/Developer/Xcode/DerivedData`
*   **Docker 시스템 청소:** 사용하지 않는 컨테이너, 이미지, 볼륨이 쌓여 있다면 터미널에 아래 명령어를 입력해 일괄 정리합니다. 이 작업만으로도 보통 20GB 이상이 확보됩니다.
    ```bash
    docker system prune -a --volumes
    ```

> 💡 **팁:** `~/Library/Caches` 폴더 자체를 통째로 지우는 행위는 절대 금물입니다. 특정 앱의 세션 정보나 로그인 상태가 풀려 업무에 지장을 줄 수 있으므로, 시각화 도구로 확인 후 용량이 비정상적으로 큰 특정 앱의 하위 캐시 폴더만 골라 지워야 합니다.

### 4단계: 대용량 파일 정리 및 자동화 규칙 만들기
마지막으로 다운로드 폴더와 데스크톱에 방치된 대용량 파일들을 정리합니다. 특히 웹 브라우저로 다운로드한 파일들은 30일이 지나면 사실상 다시 열어보지 않는 경우가 90% 이상입니다.

*   **사진 앱 최적화:** 사진 앱을 사용한다면 `설정 → iCloud`에서 “**이 Mac 저장 공간 최적화**”를 체크하세요. 원본은 iCloud에 보관되고 맥에는 최적화된 용량의 이미지 페이로드만 남게 되어 순식간에 수십 GB를 아낄 수 있습니다.

## 용량 회수 효과와 위험도 비교

무조건 많이 지우는 것보다 위험도를 고려해 정리 우선순위를 정하는 것이 현명합니다. 아래 표를 기준으로 안전한 항목부터 순차적으로 정리해 보세요.

| 정리 대상 항목 | 평균 회수 용량 | 위험도 | 영향 및 주의사항 |
| :--- | :--- | :--- | :--- |
| **로컬 스냅샷** | 10～80 GB | **낮음** | 백업이 완료된 상태라면 시스템 영향 없음 |
| **Xcode DerivedData** | 5～40 GB | **낮음** | 다음 빌드 시 첫 빌드 속도가 약간 느려짐 |
| **도커(Docker) 이미지** | 10～60 GB | **중간** | 사용 중인 이미지는 재빌드/다운로드 필요 |
| **시스템 라이브러리 임의 삭제** | 가변 | **높음** | 시스템 부팅 불가 또는 앱 크래시 유발 (권장하지 않음) |

## 실무에서 바로 쓰는 저장 공간 유지관리 팁

*   **외장 SSD 아카이빙:** 완료된 프로젝트 폴더는 내장 디스크에 두지 말고, 분기마다 외장 SSD로 옮기는 '아카이브 데이'를 팀 내 규칙으로 정하세요. 내장 용량을 항상 30% 이상 비워두는 가장 확실한 방법입니다.
*   **메시지 첨부 파일 자동 관리:** 메시지(Messages) 앱으로 주고받은 고화질 이미지와 영상도 용량을 크게 차지합니다. 메시지 앱 설정에서 "메시지 유지" 옵션을 '평생'에서 ‘**1년**’ 또는 ‘**30일**’로 변경하면 백그라운드에서 자동으로 정리됩니다.
*   **메일 첨부 파일 로컬 저장 제한:** 기본 메일(Mail) 앱은 첨부 파일을 로컬에 중복 보관하는 경향이 있습니다. 계정 설정에서 첨부 파일 다운로드 옵션을 '최근 항목만' 또는 '요청 시에만'으로 변경하세요.

## 한 걸음 더 — 용량이 다시 차지 않게 만드는 유지 규칙

한 번 저장 공간을 대대적으로 정리하고 나면 대개 두세 달 뒤에 다시 원래대로 용량이 꽉 차는 현상을 겪게 됩니다. 유입 경로를 제어하지 않았기 때문입니다. 이를 방지하기 위한 가장 효과적인 규칙은 **다운로드 폴더의 자동 정리**입니다. macOS의 '단축어(Shortcuts)' 앱이나 외부 유틸리티인 Hazel을 활용해 "생성일 또는 마지막으로 연 날짜가 30일 이상 지난 파일은 '임시 아카이브' 폴더로 자동 이동"하는 규칙을 걸어두세요. 이렇게 하면 다운로드 폴더가 쓰레기통처럼 변하는 것을 원천 차단할 수 있습니다.

두 번째는 **프로젝트 종료 체크리스트**의 도입입니다. 팀 단위로 프로젝트가 끝나는 시점에 결과물(최종 산출물)만 클라우드나 NAS에 업로드하고, 작업 과정에서 발생한 중간 렌더 캐시, 프록시 파일, 테스트용 시안 파일들은 로컬 디스크에서 즉시 삭제하는 단계를 체크리스트에 공식적으로 포함시키는 것입니다. 이 사소한 습관 하나가 팀원 전체의 맥 성능을 쾌적하게 유지해 줍니다.

마지막으로, 용량 부족 경고가 뜨기 전에 선제적으로 대응하는 일정을 만드세요. **매달 1일 아침, 딱 5분 동안만** 저장 공간 화면을 열어보는 반복 캘린더 일정을 등록해 두는 것입니다. 문제가 커지기 전에 조기에 잔여물을 발견하면, 서드파티 청소 앱을 쓰거나 시스템을 포맷해야 하는 번거로운 대청소 자체가 필요 없어집니다. 만약 이러한 관리에도 불구하고 항상 용량이 부족하다면 작업 방식을 근본적으로 바꿀 때입니다. 최근 출시되는 USB4 및 Thunderbolt 외장 NVMe SSD는 내장 SSD와 체감 속도 차이가 거의 없습니다. 대용량 미디어나 데이터 세트를 다룬다면 프로젝트 작업 디렉터리 자체를 외장 SSD로 완전히 이원화하는 구조를 적극 권장합니다.

## 자주 묻는 질문과 해결책 (Q&A)

**Q. 캐시 파일과 스냅샷을 지웠는데도 저장 공간 표시가 즉시 업데이트되지 않습니다. 이유가 무엇인가요?**  
A. macOS의 APFS 파일 시스템은 용량 계산을 백그라운드에서 비동기적으로 처리합니다. 대용량 파일을 지운 후 휴지통을 비웠더라도 시스템이 이를 여유 공간으로 인식하는 데 약간의 시간이 걸립니다. 가장 확실한 방법은 휴지통을 비운 뒤 맥을 **재부팅**하고 3～5분 정도 대기하는 것입니다.

**Q. 유명 소프트웨어인 CleanMyMac 같은 청소 도구를 팀원들에게 일괄 배포해도 괜찮을까요?**  
A. 도구 자체는 훌륭하지만, 기술적 이해도가 낮은 상태에서 일괄 배포하는 것은 추천하지 않습니다. 시스템 깊숙한 곳의 라이브러리나 개발 환경 설정 파일까지 캐시로 인식해 지워버려 업무 환경이 깨지는 부작용이 빈번하게 발생하기 때문입니다. 용량 파악은 앞서 소개해 드린 시각화 도구(GrandPerspective 등)로 직접 진행하고, 삭제는 사용자가 명확히 아는 범위 내에서 수동으로 진행하는 것이 가장 안전합니다.

**Q. 외장 SSD를 상시 연결해 작업 공간으로 쓰고 싶습니다. 속도 저하나 끊김 현상은 없나요?**  
A. 10Gbps 이상을 지원하는 NVMe 외장 SSD 케이스와 고품질 케이블을 사용하면 일반적인 개발 작업, 포토샵 디자인, 4K 영상 편집에서도 내장 드라이브와 체감 성능 차이를 느끼기 어렵습니다. 다만, 허브를 거치지 않고 맥북 본체의 썬더볼트 포트에 직접 연결해야 대역폭 손실 없이 안정적인 속도가 나옵니다.
