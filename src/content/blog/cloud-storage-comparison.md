## 클라우드 스토리지 비교: 용량당 가격과 실사용 속도 정리

클라우드 스토리지를 고를 때 대부분 "하나의 서비스에 모든 데이터를 몰아넣는 것"을 먼저 떠올립니다. 하지만 실제 업무와 개인 데이터를 운용해 보면, 단 하나의 서비스만 고집하기보다 **역할을 명확히 나누어 두 개 이상의 서비스를 조합해 사용하는 편이 비용 절감과 데이터 안전성 측면에서 훨씬 유리**합니다.

구글 드라이브, iCloud, 원드라이브, 드롭박스, Sync 등 대표적인 5개 서비스에 동일한 파일 세트(10GB 크기의 영상 1개, 10,000개의 소용량 코드/텍스트 파일, PSD 작업 파일 등)를 직접 올리고 동기화 속도를 측정해 보았습니다.

### 단일 클라우드 종속에서 벗어나야 하는 이유

왜 여러 클라우드를 조합해야 할까요? 실무에서 체감하는 대표적인 이유는 다음 세 가지입니다.

1. **무료 15GB 용량의 한계**: 고해상도 사진과 4K 영상 촬영이 보편화되면서 구글 드라이브나 원드라이브가 제공하는 기본 무료 용량(5GB～15GB)은 수개월 내에 채워집니다.
2. **동기화 엔진에 따른 체감 속도 격차**: 서비스마다 백그라운드 파일 처리 방식(전체 재업로드 vs 블록 단위 동기화)이 달라, 대용량 디자인 파일이나 코딩 프로젝트 관리 시 속도 차이가 수십 배 이상 벌어집니다.
3. **계정 정지 및 단일 실패 지점(Single Point of Failure) 위험**: 결제 오류나 자동 보안 시스템의 오탐으로 인해 계정이 잠길 경우, 모든 개인 파일 및 작업 자료에 대한 접근이 즉시 차단될 위험이 있습니다.

### 클라우드 세팅 전 준비사항

본격적인 서비스 선택 및 구조화에 앞서 다음 세 가지 항목을 먼저 점검하시기 바랍니다.

- **현재 사용 중인 실제 데이터 용량 측정**: 스마트폰 사진, 문서, 진행 중인 프로젝트, 아카이빙용 데이터의 용량을 각각 구분해 집계합니다.
- **주요 협업 대상의 생태계 파악**: 함께 작업하는 팀원이나 거래처가 구글 워크스페이스를 쓰는지, 마이크로소프트 365(MS 365)를 쓰는지 확인합니다.
- **실제 업로드 속도 테스트 준비**: 1GB 분량의 단일 파일과 1,000개의 소용량 파일이 담긴 폴더를 준비하여 실제 사용하는 네트워크 환경에서 업로드 속도를 직접 테스트합니다.

### 단계별 클라우드 스토리지 최적화 가이드

#### 1단계: 데이터를 세 종류로 나누기
모든 데이터를 똑같은 기준 관리할 필요는 없습니다. 데이터를 다음 3가지 유형으로 분류하세요.
- **작업 파일**: 매일 수정하고 열어보는 PSD, AI, 소스코드, 문서 파일
- **협업 문서**: 팀원과 실시간으로 동시에 편집하는 스프레드시트 및 기획서
- **보관 자료(아카이브)**: 거의 열어보지 않지만 손실되면 안 되는 과거 프로젝트, 백업 사진

> 💡 **에디터 팁**: 자주 접근하지 않는 1TB 이상의 아카이브 자료는 유료 클라우드에 두는 것보다 외장 SSD 2차 백업과 AWS S3 Glacier 같은 저가형 아카이브 요금제를 조합하는 것이 장기적으로 훨씬 비용이 절약됩니다.

#### 2단계: 협업 문서는 상대방의 생태계에 맞추기
실시간 공동 편집 환경에서는 파일 공유 및 권한 설정 과정의 번거로움을 줄이는 것이 핵심입니다. 
- 조직이나 클라이언트가 **구글 워크스페이스** 중심이라면 `Google Drive`를 주 협업 공간으로 설정합니다.
- **MS Office(Word, Excel, PowerPoint)** 중심 환경이라면 `OneDrive`를 사용하는 것이 파일 깨짐이나 권한 오류로 인한 시간 낭비를 방지합니다.

> 💡 **에디터 팁**: 외부 인원에게 공유 링크를 보낼 때는 [링크 속성]에서 만료일(Expiration Date)과 접근 비밀번호를 반드시 지정하세요.

#### 3단계: 동기화 방식 차이 확인하기
서비스별 동기화 구조를 이해해야 병목 현상을 막을 수 있습니다.
- **드롭박스(Dropbox)**: 파일의 수정된 부분만 전송하는 '블록 단위 델타 동기화(Delta Sync)'를 지원하므로, 몇 GB짜리 대용량 작업 파일을 살짝 수정했을 때 업로드 속도가 독보적으로 빠릅니다.
- **iCloud / 구글 드라이브**: 파일 단위 처리 비중이 높아, 파일 수정을 완료할 때마다 전체 파일이 다시 업로드되어 백그라운드 네트워크 자원을 더 소비합니다.

> 💡 **에디터 팁**: '스마트 동기화' 또는 '공간 절약(On-Demand)' 옵션은 하드 용량을 아껴주지만, 인터넷이 안 되는 환경으로 이동하기 전에는 대상 폴더 오른쪽 클릭 후 `항상 이 디바이스에 유지`를 선택해 두어야 합니다.

#### 4단계: 2차 백업 경로 만들기
메인으로 사용하는 클라우드가 구글 드라이브라면, 중요한 핵심 작업 폴더만 원드라이브나 드롭박스로 자동 교차 복제되도록 설정합니다. rclone이나 각 서비스의 내보내기 기능으로 자동화하면 관리 부담이 거의 없습니다.

> 💡 **에디터 팁**: 계정 정지 위험을 줄이려면 결제 수단과 복구 이메일을 서비스별로 다르게 두세요.

### 실무 생산성을 높이는 클라우드 운용 팁

1. **가족 요금제(Family Plan) 적극 활용**: 구글 원이나 iCloud+, MS 365 등은 가족 공유 기능을 통해 5～6명이 용량을 나누어 쓸 수 있습니다. 1인당 실제 부담 금액이 50% 이상 저렴해집니다.
2. **사진 저장 품질 설정 검토**: 사진은 원본 유지 여부를 먼저 정하세요. Google 포토나 iCloud 사진 관리 시 웹/모바일 감상용은 고품질 압축 저장으로 변경하면 필요한 용량이 절반 이하가 됩니다.
3. **개인 계정과 업무 계정의 완벽한 분리**: 업무 파일을 개인 계정에 두면 퇴사나 회사 감사 시 법적/기술적 문제가 생깁니다. 처음부터 OS 사용자 계정이나 클라우드 프로필을 이중화하세요.

### 자주 묻는 질문 (FAQ) 및 문제 해결

**Q1. 무료 계정을 여러 개 쓰는 건 어떤가요?**
> A1. 단기적으로는 가능하지만 시간이 지나면 파일이 어디 있는지 추적이 안 되는 순간 복구 비용이 요금보다 커집니다. 최소한 주 저장소 하나는 유료 계정으로 통합하세요.

**Q2. 동기화 폴더가 갑자기 용량을 다 먹습니다.**
> A2. 온디맨드(스트리밍) 설정이 꺼져 전체가 로컬로 내려온 경우입니다. 각 앱의 "공간 절약" 또는 "온라인 전용" 옵션을 켜고 필요한 폴더만 오프라인 유지로 지정하세요.
> - **OneDrive**: `설정 > Sync and backup > Advanced settings > Files On-Demand` 활성화
> - **Google Drive**: `설정 > 마이컴퓨터/구글드라이브 > 파일 스트리밍`으로 변경

**Q3. 클라우드만 있으면 백업은 끝인가요?**
> A3. 아닙니다. 동기화는 삭제와 랜섬웨어 암호화까지 그대로 전파합니다. 서비스별 버전 기록 보존 기간(보통 30일～180일)을 확인하고, 별도 스냅샷 백업을 병행하세요.

### 한 걸음 더 — rclone으로 서비스 간 복제 자동화하기

두 번째 백업 경로를 손으로 유지하는 것은 오래가지 않습니다. rclone은 대부분의 클라우드 서비스를 지원하는 무료 도구로, 한 서비스의 폴더를 다른 서비스로 주기적으로 복제할 수 있습니다. 

```bash
# 구글 드라이브의 '작업' 폴더를 원드라이브의 '백업/작업' 폴더로 복제 테스트
rclone sync gdrive:작업 onedrive:백업/작업 --dry-run
```

`rclone sync gdrive:작업 onedrive:백업/작업 --dry-run`처럼 먼저 시험 실행으로 무엇이 옮겨질지 확인한 뒤 실제 동기화를 돌리는 순서를 지키면 사고를 피할 수 있습니다.

주의할 점은 `sync`가 대상 쪽의 없는 파일을 삭제한다는 것입니다. 원본에서 실수로 지운 파일이 백업에서도 사라지므로, 백업 목적이라면 `copy`를 쓰거나 `--backup-dir` 옵션으로 삭제 대상을 별도 폴더에 남기는 편이 안전합니다.

```bash
# 삭제되는 파일을 날짜별 격리 폴더로 보관하며 동기화
rclone sync gdrive:작업 onedrive:백업/작업 --backup-dir onedrive:삭제보관소/$(date +%Y%m%d)
```

여기에 `--max-age 30d` 같은 조건을 붙여 최근 파일만 복제하면 트래픽과 시간을 줄일 수 있습니다. 스케줄러(Windows 작업 스케줄러, macOS cron)에 등록해 두면 이후로는 신경 쓸 일이 거의 없습니다.

요금제를 정할 때는 1년 뒤 사용량을 기준으로 삼으세요. 사진과 영상은 매년 일정하게 늘어나므로 지금 딱 맞는 용량을 고르면 몇 달 뒤 다시 결정해야 합니다. 반대로 지나치게 큰 용량은 정리 동기를 없애 불필요한 파일이 쌓이게 만듭니다. 현재 사용량의 1.5배 정도가 대체로 적절하며, 연간 결제 할인은 서비스 만족도를 6개월 이상 확인한 뒤에 선택하는 편이 안전합니다.

### 마무리하며

결론은 단순합니다. **협업용 한 곳, 백업용 한 곳.** 이 두 축만 정하면 나머지 선택은 가격 비교로 끝납니다. 

자신의 주 작업 환경에 맞춰 메인 클라우드를 고르고, 2차 백업망을 최소한의 비용으로 자동 구축해 보세요. 데이터 손실 걱정 없이 중요한 작업에만 온전히 집중할 수 있게 될 것입니다.
