무거운 유료 프로그램을 깔거나 복잡한 코딩을 배울 필요 전혀 없습니다. 하루 대부분의 시간을 보내는 VS Code가 느려지고 버벅거리는 이유는 대부분 무분별하게 설치된 확장 프로그램 때문입니다. 실제로 얼마 전 개발팀 김 대리가 에디터가 자꾸 멈춘다며 SOS를 요청해 확인해보니, 설치된 확장만 38개에 달했고 에디터 로딩에만 12초, 메모리는 2.4GB를 점유하고 있었습니다. 

지금 당장 별도 프로그램 설치 없이, 에디터 자체 기본 기능과 단축키 튜닝만으로 속도를 3배 이상 끌어올리는 초간단 **5분 완성 3단계 가이드**를 제시합니다. 

1. **[1단계: 무거운 확장 진단]** `F1` 키를 누르고 `Developer: Startup Performance`를 입력해 로딩 속도를 잡아먹는 범인을 찾습니다.
2. **[2단계: 핵심 기본값 변경]** `settings.json`을 열어 자동 저장, 포맷팅, 스티키 스크롤 등 필수 3개 옵션을 활성화합니다.
3. **[3단계: 단축키 손끝 세팅]** 마우스 이동을 줄이는 4대 필수 단축키(`Cmd/Ctrl + P`, `Cmd/Ctrl + D` 등)를 몸에 익힙니다.

이 3단계만 진행해도 에디터 반응 속도가 몰라보게 가벼워집니다. 수년간 에디터 세팅으로 수많은 시행착오를 겪으며 최종적으로 남겨둔 핵심 세팅과 진짜 필요한 필수 확장 10선 튜닝법을 상세히 정리해 드립니다.

## 1. 기본 설정 튜닝: 확장 프로그램 5개보다 강력한 내장 기능

확장 프로그램을 추가하기 전에 VS Code가 기본으로 제공하는 강력한 옵션부터 켜야 합니다. 설정을 클릭해서 일일이 찾지 말고, 단축키로 설정 파일에 직접 접근하는 것이 훨씬 빠릅니다.

### settings.json 직접 편집하기
`Cmd + Shift + P`(macOS) 또는 `Ctrl + Shift + P`(Windows)를 누른 뒤 `Open User Settings (JSON)`을 입력하여 파일 형태로 설정을 열어줍니다. 아래 핵심 코드를 추가하세요.

```json
{
  "files.autoSave": "onFocusChange",
  "editor.formatOnSave": true,
  "editor.stickyScroll.enabled": true
}
```

- **`files.autoSave`: "onFocusChange"**  
  창을 벗어나거나 다른 파일로 이동할 때 자동으로 저장됩니다. 작업 흐름이 깨지지 않고 습관적인 `Cmd/Ctrl + S` 누르기에서 벗어날 수 있어 하루 평균 200회 이상의 불필요한 키 입력이 줄어듭니다.
- **`editor.formatOnSave`: true**  
  저장 시점에 자동으로 코드를 깔끔하게 정돈합니다. 팀원 간의 들여쓰기나 줄바꿈 스타일 충돌을 근본적으로 차단합니다.
- **`editor.stickyScroll.enabled`: true**  
  긴 코드나 문서 작업 시, 현재 내가 보고 있는 함수나 클래스의 선언부가 상단에 고정되어 위치를 헤매지 않도록 돕습니다.

> 💡 **팁:** `settings.json` 파일 내에서 `Cmd/Ctrl + Space`를 누르면 설정 가능한 모든 키값의 자동 완성이 표시되어 오탈자 없이 빠르게 세팅할 수 있습니다.

## 2. 마우스에 손 올리는 횟수를 50% 줄이는 4대 단축키

파일 탐색기 패널을 열어 마우스로 클릭하고 헤매는 시간만 줄여도 업무 시간이 수십 분 단축됩니다. 다음 4가지 핵심 내장 단축키는 반드시 손에 익혀두어야 합니다.

1. **`Cmd/Ctrl + P` (Quick Open / 파일 이동)**
   - 파일명 일부만 입력해도 즉시 이동합니다.
   - **응용 팁:** 입력창에 `@`를 붙이면 해당 파일의 주요 메서드/심볼 목록으로, `:`를 붙이면 원하는 줄 번호로 즉시 이동합니다 (예: `app.js:145`).
2. **`Cmd/Ctrl + Shift + F` (전체 검색)**
   - 프로젝트 전체 내에서 텍스트를 검색합니다. 세부 옵션에서 제외할 폴더(`node_modules` 등)를 지정하면 검색 속도가 5배 이상 빨라집니다.
3. **`F12` (정의로 이동 - Go to Definition)**
   - 변수나 함수가 정의된 원래 위치로 단번에 이동합니다. 돌아올 때는 `Alt + Left Arrow`(macOS: `Ctrl + -`)를 누르면 됩니다.
4. **`Cmd/Ctrl + D` (다음 동일 항목 멀티 선택)**
   - 단어를 드래그한 상태에서 누를 때마다 동일한 단어가 순차적으로 멀티 커서로 선택됩니다. 변수명을 한 번에 변경할 때 매우 유용합니다.

> 💡 **팁:** 터미널을 열기 위해 마우스를 아래로 드래그할 필요 없이 `Ctrl + ` ` (백틱) 단축키 하나로 내장 터미널을 토글하세요.

## 3. 슬기로운 확장 다이어트: 역할별 추천 확장 10선

동일한 기능을 수행하는 확장이 중복 설치되어 있으면 에디터 충돌의 주원인이 됩니다. 꼭 필요한 역할별로 검증된 최적의 10가지 확장만 남겨두세요.

1. **GitLens**: 코드 줄마다 작성자와 커밋 메시지를 보여주어 이력 추적 시간을 단축합니다.
2. **Error Lens**: 문제 패널을 굳이 열지 않아도 에러 및 경고 메시지를 코드 줄 위에 즉시 텍스트로 보여줍니다.
3. **Prettier - Code formatter**: 코드 스타일을 통일시켜 주는 필수 포맷터입니다.
4. **ESLint / Pylint**: 사용하는 언어에 맞춰 문법 오류 및 잠재적 버그를 실시간 감지합니다.
5. **Remote - SSH**: 원격 서버의 파일 환경을 로컬 에디터처럼 원활하게 조작합니다.
6. **REST Client**: Postman 같은 별도 앱 없이 `.http` 파일 하나로 API 요청 및 테스트를 수행합니다.
7. **Path Intellisense**: 파일 경로 작성 시 폴더 및 파일명을 자동으로 완성해 줍니다.
8. **Auto Rename Tag**: HTML/XML 태그 수정 시 짝이 되는 닫는 태그를 자동으로 함께 바꿔줍니다.
9. **Code Spell Checker**: 코드 내 영문 오탈자를 잡아주어 사소한 이름 오류로 인한 버그를 방지합니다.
10. **Bookmarks**: 코드 특정 위치에 책갈피를 지정하여 대용량 파일 간 이동을 용이하게 합니다.

### 역할별 핵심 확장 요약

| 역할 | 추천 확장 | 핵심 이유 |
| :--- | :--- | :--- |
| **Git 이력 확인** | GitLens | 줄 단위 작성자, 커밋 메시지, 날짜 즉시 표시 |
| **오류 가시성** | Error Lens | 문제 하단 패널을 클릭할 필요 없이 코드에 직관적 표시 |
| **원격 작업** | Remote - SSH | 로컬 VS Code 환경 그대로 서버 코드 직접 수정 |
| **API 테스트** | REST Client | 별도 앱 실행 없이 `.http` 스크립트로 버전 관리 가능 |

> 💡 **팁:** 프로젝트별로 필요한 확장이 다를 경우, 팀원들과 동유할 수 있도록 프로젝트 최상단에 `.vscode/extensions.json` 파일을 만들어 `recommendations` 배열에 확장 ID를 적어두세요. 프로젝트를 열 때 자동으로 설치 안내 메시지가 뜹니다.

## 4. 한 걸음 더 — 프로필과 작업 영역으로 환경 분리하기

VS Code의 **프로필(Profiles)** 기능은 확장 프로그램 과잉 문제를 구조적으로 해결해 줍니다. 언어나 업무 성격별로 프로필을 분리해 두면 필요할 때 해당 환경의 확장만 로드되어 초기 시작 속도와 메모리 사용량을 대폭 절감할 수 있습니다.

- **프로필 분리 전략**
  - **문서 작업 프로필**: Markdown 확장, 스펠 체크 확장만 활성화
  - **백엔드 개발 프로필**: Remote - SSH, REST Client, DB 관련 확장만 활성화
  - **프론트엔드 개발 프로필**: Prettier, HTML/CSS 관련 확장 활성화

좌측 하단 톱니바퀴 아이콘 $\rightarrow$ **Profiles** 메뉴에서 새로운 프로필을 생성할 수 있으며, 내보내기/불러오기 링크를 활용해 팀원 온보딩 용도로 세팅을 공유할 수도 있습니다.

또한 프로젝트별 규칙은 `.vscode/settings.json` 작업 영역 설정에 작성하여 Git에 커밋하세요. 개인이 사용하는 글꼴이나 테마는 '사용자 설정(User Settings)'에 두고, 들여쓰기 크기나 포맷터 규칙은 '작업 영역 설정(Workspace Settings)'에 두는 경계만 명확히 지키면 설정 충돌로 낭비되는 시간이 완벽히 사라집니다.

## 5. 트러블슈팅 & 자주 묻는 질문 (FAQ)

### Q1. 에디터가 갑자기 버벅거리고 반응 속도가 늦어집니다. 원인을 어떻게 찾나요?
> **A:** `F1` 키를 누른 뒤 `Extension Bisect`를 실행해 보세요. 에디터가 확장을 절반씩 비활성화하면서 테스트를 진행해 문제 원인이 되는 확장을 이분 탐색법으로 정확히 찾아내 줍니다. 또한 `Help` $\rightarrow$ `Toggle Developer Tools` 메뉴를 열어 콘솔 탭에서 과도한 파일 감시(File Watcher) 에러가 발생하는지 점검하세요.

### Q2. 파일 저장 시 포맷팅이 작동하지 않거나 포맷터가 제각각 다르게 동작합니다.
> **A:** 여러 포맷터 확장이 충돌하는 경우입니다. `settings.json`에 명시적으로 기본 포맷터를 지정해야 합니다. 예를 들어 JavaScript 환경이라면 아래 구문을 추가해 언어별 포맷터를 고정하세요.
> ```json
> "[javascript]": {
>   "editor.defaultFormatter": "esbenp.prettier-vscode"
> }
> ```

### Q3. 로그 파일이나 100MB 이상의 대용량 파일을 열면 VS Code가 멈춥니다.
> **A:** 구문 강조(Syntax Highlighting)와 파일 감시 스레드가 과부하를 일으키는 현상입니다. 메모리 제한을 늘리기 위해 `settings.json`에 `"files.maxMemoryForLargeFilesMB": 4096`을 추가하거나, 대용량 파일 파싱을 방지하도록 설정하세요. 대용량 텍스트나 로그 확인은 에디터 대신 전용 뷰어나 CLI 명령어(`tail`, `less`)를 사용하는 것이 안전합니다.

## 마무리

생산성을 올리는 가장 빠른 방법은 무언가를 더 추가하는 것이 아니라, 불필요한 것을 비워내는 것입니다. 지금 설치되어 있는 확장 프로그램 목록을 열어보고, 최근 1개월간 단 한 번도 쓰지 않은 확장은 주저 없이 삭제해 보세요. 

슬림하게 튜닝된 기본 에디터 성능과 체화된 몇 가지 단축키만으로도 여러분의 퇴근 시간이 훨씬 앞당겨질 것입니다.
