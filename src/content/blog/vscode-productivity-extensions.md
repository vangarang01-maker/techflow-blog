개발 도구의 성능과 편의성을 높이기 위해 수많은 확장을 설치하지만, 아이러니하게도 확장을 많이 깔수록 VS Code의 반응 속도는 점점 느려집니다. 테크플로우에서 지난 6개월 이상 지우지 않고 끝까지 남겨둔 핵심 확장 10개와, 확장 설치보다 더 큰 성능 개선 효과를 가져오는 기본 설정 튜닝값을 상세히 정리했습니다.

## 개발 환경 튜닝이 필요한 이유

개발자가 하루 중 가장 오랜 시간 바라보는 창은 단연 코드 에디터입니다. 에디터에서 발생하는 0.5초의 지연이나 번거로운 마우스 클릭이 하루 동안 수십, 수hundred 번 누적되면 집중력이 크게 깨집니다. 

하지만 많은 개발자가 불편함을 느낄 때마다 무작정 새로운 확장을 추가하곤 합니다. 확장 프로그램의 과도한 설치는 VS Code의 초기 구동 시간을 늘리고, 메모리 점유율을 높이며, 확장 간의 충돌로 인해 원인을 알 수 없는 오류를 발생시킵니다. VS Code가 제공하는 기본 설정 기능만 제대로 활용해도 필요한 확장의 절반은 정리할 수 있습니다.

## 작업 시작 전 준비 사항

실전 가이드를 따라 하기 전에 아래 준비 사항을 미리 확인해 주시기 바랍니다.

- 최신 버전의 VS Code 설치 및 설정 동기화(Settings Sync) 계정 로그인
- 현재 터미널에 설치된 확장 목록 확인 (`code --list-extensions` 명령 실행)
- 주로 사용하는 주요 개발 언어 1～2개 선별

## 4단계 VS Code 생산성 튜닝 실전 가이드

### 1단계: 기본 설정(settings.json) 튜닝으로 속도 올리기

기본 텍스트 에디터 설정을 튜닝하는 것만으로도 5개 이상의 확장을 대체할 수 있습니다. 특히 파일 자동 저장과 포맷팅, 코드 구조를 보여주는 스티키 스크롤(Sticky Scroll) 설정은 체감 생산성을 대폭 향상시킵니다.

`Cmd + Shift + P`(Windows/Linux는 `Ctrl + Shift + P`)를 눌러 명령 팔레트를 연 뒤 `Preferences: Open User Settings (JSON)`을 검색하여 선택합니다. 직접 `settings.json` 파일에 아래 구문을 추가하거나 수정합니다.

```json
{
  "files.autoSave": "onFocusChange",
  "editor.formatOnSave": true,
  "editor.stickyScroll.enabled": true,
  "editor.minimap.enabled": false,
  "editor.renderWhitespace": "selection"
}
```

`files.autoSave`를 `onFocusChange`로 설정하면 포커스가 다른 창으로 이동할 때 알아서 저장되어 저장 단축키를 누르는 번거로움이 사라집니다. `editor.stickyScroll.enabled`를 `true`로 켜면 클래스나 함수 영역의 상단 선언부가 고정되어 긴 코드를 읽을 때 현재 위치를 즉시 파악할 수 있습니다.

### 2단계: 핵심 검색 및 이동 단축키 익히기

마우스로 탐색기 창을 클릭해 파일을 찾는 동작은 대표적인 시간 낭비 요소입니다. 아래 4가지 단축키 조합을 몸에 익히는 것만으로도 작업 속도가 2배 이상 빨라집니다.

1. **파일 빠른 이동**: `Cmd/Ctrl + P`를 누르고 파일 이름의 일부만 입력하여 즉시 이동합니다.
2. **프로젝트 전체 검색**: `Cmd/Ctrl + Shift + F`를 통해 전체 프로젝트 내 문자열을 검색합니다.
3. **심볼 정의로 이동**: 변수나 함수 이름 위에 커서를 두고 `F12`를 누르면 선언 위치로 바로 이동합니다.
4. **다음 동일 항목 선택 (멀티커서)**: 단어를 선택한 상태에서 `Cmd/Ctrl + D`를 누르면 다음으로 일치하는 단어가 연속 선택되어 일괄 수정이 가능합니다.

> **단축키 팁**: `Cmd/Ctrl + P` 입력창에서 맨 앞에 `@`를 붙이면 현재 파일 내의 함수와 변수(심볼) 목록만 추려내며, `:`를 붙이고 숫자를 입력하면 해당 줄 번호로 즉시 이동합니다.

### 3단계: 역할별 필수 확장 10선 정립하기

확장 프로그램은 동일한 기능을 수행하는 도구가 중복되지 않도록 역할별로 하나씩만 남겨두어야 합니다. 테크플로우에서 엄선한 10가지 필수 확장은 다음과 같습니다.

1. **GitLens**: 코드 줄마다 작성자와 커밋 메시지를 실시간으로 보여주어 이력 추적을 돕습니다.
2. **Error Lens**: 문제 패널을 열지 않아도 에러와 경고 문구를 코드 줄 바로 옆에 인라인으로 출력합니다.
3. **Remote - SSH**: 원격 서버 환경에 접속하여 로컬 에디터와 동일한 환경에서 작업하게 해줍니다.
4. **REST Client**: HTTP 요청을 `.http` 파일로 작성하여 Postman 없이 API를 테스트할 수 있게 합니다.
5. **Prettier - Code formatter**: 프로젝트의 코드 스타일을 일관되게 자동으로 정돈합니다.
6. **ESLint** (또는 언어별 Linter): 코드 스타일 및 잠재적 구문 오류를 즉시 감지합니다.
7. **Auto Rename Tag**: HTML/XML 태그 수정 시 쌍이 되는 반대쪽 태그를 자동으로 변경합니다.
8. **Path Intellisense**: 파일 경로 작성 시 프로젝트 내부 경로를 자동 완성을 통해 안내합니다.
9. **Docker**: 컨테이너, 이미지, 볼륨 상태를 에디터 내부에서 관리하도록 돕습니다.
10. **Todo Highlight**: 코드 내 `TODO:`, `FIXME:` 주석에 하이라이트를 적용해 시각적 가시성을 높입니다.

프로젝트 팀원들과 동일한 확장을 공유하려면 저장소 루트에 `.vscode/extensions.json` 파일을 생성하고 다음과 같이 권장 확장을 등록해 두는 것이 좋습니다.

```json
{
  "recommendations": [
    "eamodio.gitlens",
    "usernamehw.errorlens",
    "esbenp.prettier-vscode"
  ]
}
```

### 4단계: 사용자 스니펫과 작업 영역 정리하기

자주 반복 작성하는 Boilerplate 코드는 스니펫(Code Snippet)으로 등록해 둡니다. `Preferences: Configure User Snippets`로 들어가 사용 중인 언어(예: `typescriptreact.json`)를 선택하고 규칙을 등록하면 단 몇 글자의 입력만으로 긴 코드 블록을 불러올 수 있습니다.

또한 여러 폴더를 동시에 다루거나 프로젝트별로 서로 다른 설정을 적용해야 할 때는 `.code-workspace` 파일을 사용합니다. 작업 영역 단위로 활성화할 확장과 전용 설정값을 묶어두면 프로젝트 전환 시 불필요한 확장이 실행되지 않아 시작 속도가 빨라지고 메모리 부담이 줄어듭니다.

## 역할별 추천 확장 비교

자주 쓰이는 주요 확장들의 역할과 핵심 도입 이유를 정리한 표입니다.

| 역할 | 추천 확장 | 핵심 이유 |
| :--- | :--- | :--- |
| Git 이력 확인 | GitLens | 줄 단위 작성자·커밋 메시지 즉시 표시 |
| 오류 가시성 | Error Lens | 하단 문제 패널을 별도로 열지 않아도 됨 |
| 원격 작업 | Remote - SSH | 원격 서버 환경을 로컬 에디터처럼 사용 |
| API 테스트 | REST Client | `.http` 파일로 API 요청을 버전 관리 가능 |

## 에디터 가속을 위한 실전 팁

> **팁 1**: 터미널에서 `code .` 명령으로 현재 폴더를 직접 여는 습관을 들이면 마우스로 파일 탐색기를 열고 폴더를 드래그하는 시간을 완전히 줄일 수 있습니다.

> **팁 2**: VS Code의 '설정 동기화(Settings Sync)' 기능을 켜두면 새 기기나 다른 컴퓨터에서 작업할 때 5분 이내에 기존 환경을 그대로 복원할 수 있습니다.

> **팁 3**: 확장의 성능 영향을 확인하려면 명령 팔레트(`Cmd/Ctrl + Shift + P`)에서 `Developer: Startup Performance`를 실행하세요. 각 확장이 부팅 시 소비한 정확한 시간(ms)을 확인할 수 있습니다.

## 한 걸음 더 — 프로필과 작업 영역으로 환경 분리하기

VS Code의 프로필(Profiles) 기능은 확장 과잉으로 인한 에디터 저하 문제를 구조적으로 해결해 줍니다. 언어나 업무 성격별로 프로필을 분리해 두면, 해당 작업 시 필요한 확장만 선별적으로 활성화되므로 에디터 시작 속도와 메모리 점유율이 획기적으로 개선됩니다. 

예를 들어 마크다운 중심의 문서 작성 프로필에는 문서 도구만 배치하고, 백엔드 프로필에는 디버거와 데이터베이스 관련 도구만 활성화하는 식입니다. 생성한 프로필은 내보내기 링크나 JSON 형태로 팀원들에게 공유할 수 있어 신규 팀원의 온보딩 시간을 단축시키는 데도 유용합니다.

프로젝트 루트의 `.vscode/settings.json` 파일은 프로젝트 고유의 규칙을 설정하는 공간입니다. 들여쓰기 크기(tabSize), 포맷터 설정, 빌드 제외 폴더 지정 등의 항목을 이곳에 작성한 뒤 저장소에 커밋하면, 팀원 전체가 별도의 추가 설정 없이 동일한 스타일로 작업할 수 있습니다. 개인적인 취향은 사용자 설정(User Settings)에 두고, 저장소 단위의 규칙은 작업 영역 설정(Workspace Settings)에 두는 경계만 명확히 지키면 설정 충돌로 발생하는 시간 낭비를 막을 수 있습니다.

마지막으로 확신의 안전성과 신뢰성을 검증하는 습관이 필요합니다. VS Code 확장은 사용자 로컬 파일 시스템에 접근할 수 있는 권한을 가지므로 게시자의 신뢰도, 다운로드 수, 최근 업데이트 일자를 반드시 확인해야 합니다. 1년 이상 업데이트가 중단된 확장은 구문 강조 깨짐이나 메모리 누수의 주원인이 되므로, 활발히 유지보수되는 대체 확장으로 빠르게 전환하는 것을 권장합니다.

## 자주 묻는 질문 (FAQ)

### Q1. 에디터가 갑자기 느려졌는데 원인을 모르겠습니다.
상단 메뉴의 `Help → Toggle Developer Tools`를 열어 렌더링 성능 및 콘솔 오류를 확인하거나, 명령 팔레트에서 `Extension Bisect`를 실행하세요. 이등분 탐색 방식으로 문제를 일으키는 확장을 자동으로 추적해 줍니다. 대개 프로젝트 전체 디렉터리를 감시하는 확장이나 언어 서버가 원인인 경우가 많습니다.

### Q2. 포맷터가 파일을 저장할 때마다 다르게 동작하거나 작동하지 않습니다.
언어별 기본 포맷터 지정이 누락되었거나 복수의 포맷터 확장이 충돌하는 경우입니다. `settings.json` 내에 `"editor.defaultFormatter"`를 명시적으로 입력해 주어야 합니다. 

예를 들어 TypeScript 파일 환경이라면 `"[typescript]": { "editor.defaultFormatter": "esbenp.prettier-vscode" }`와 같이 언어별 포맷터를 지정하고 이를 프로젝트 내 설정 파일로 커밋하여 공유하는 것이 안전합니다.

### Q3. 대용량 로그 파일이나 대형 텍스트 파일을 열 때 에디터가 멈춥니다.
VS Code 기본 메모리 제한 대역을 넘어서는 대용량 파일은 구문 강조(Syntax Highlighting) 처리 과정에서 에디터가 멈출 수 있습니다. 

`settings.json`에서 `files.maxMemoryForLargeFilesMB` 설정값을 기본 4096(4GB) 이상으로 올려주거나, 100MB가 넘는 순수 대용량 로그 파일은 VS Code 대신 전용 뷰어나 터미널의 `less`, `tail` 명령을 사용하는 것이 효율적입니다.

## 마치며

VS Code의 생산성을 높이는 가장 좋은 방법은 새로운 확장을 계속 설치하는 것이 아니라, 매달 사용하지 않는 확장을 하나씩 지워나가는 것입니다. 불필요한 확장을 줄이고 기본 설정과 단축키를 체화할 때 가장 쾌적하고 빠른 개발 환경이 완성됩니다.
