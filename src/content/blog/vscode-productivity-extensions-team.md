개인 세팅을 팀 단위로 확장할 때는 합의와 문서화가 추가로 필요합니다. 도입 과정에서 실제로 걸린 지점 위주로 다시 정리했습니다.

확장을 많이 깔수록 느려집니다. 6개월 이상 지우지 않고 남은 10개와, 확장보다 효과가 큰 기본 설정값을 함께 정리했습니다.

**이 글에서 다루는 내용**

1. 기본 설정부터 손보기
2. 검색과 이동 단축키 몸에 붙이기
3. 확장은 역할별로 하나씩만 남기기
4. 스니펫과 작업 영역 정리하기

## 왜 지금 정리해야 할까요

- 에디터는 하루 중 가장 오래 보는 창이라 1초 단축이 누적 효과가 큽니다.
- 확장 과잉은 시작 시간과 메모리를 늘리고 충돌 원인 추적을 어렵게 만듭니다.
- 기본 기능만 제대로 알아도 확장 절반은 필요 없습니다.

## 시작 전 준비물

- VS Code 최신 버전과 설정 동기화 계정
- 현재 설치된 확장 목록(`code --list-extensions`)
- 주로 쓰는 언어 1~2개

## 단계별 실행 가이드

### 1단계 — 기본 설정부터 손보기

`files.autoSave`를 `onFocusChange`로, `editor.formatOnSave`를 켜고, `editor.stickyScroll.enabled`를 활성화합니다. 이 세 가지가 확장 다섯 개보다 체감 효과가 큽니다.

> **팁:** `settings.json`을 직접 열어 편집하면 검색보다 빠릅니다(`Cmd/Ctrl + Shift + P` → Open User Settings JSON).

### 2단계 — 검색과 이동 단축키 몸에 붙이기

`Cmd/Ctrl + P`(파일 이동), `Cmd/Ctrl + Shift + F`(전체 검색), `F12`(정의로 이동), `Cmd/Ctrl + D`(다음 동일 항목 선택)만 익혀도 마우스 사용이 절반으로 줄어듭니다.

> **팁:** `Cmd/Ctrl + P` 입력창에서 `@`는 심볼, `:`는 줄 번호로 범위를 좁힙니다.

### 3단계 — 확장은 역할별로 하나씩만 남기기

Git 보조(GitLens), 오류 표시(Error Lens), 포맷터(Prettier), 린터, 원격 개발(Remote - SSH), REST 클라이언트 정도면 대부분 커버됩니다. 같은 역할의 확장을 둘 이상 두면 충돌이 납니다.

> **팁:** 프로젝트별 권장 확장은 `.vscode/extensions.json`에 적어 팀과 공유하세요.

### 4단계 — 스니펫과 작업 영역 정리하기

반복 입력하는 코드 블록은 사용자 스니펫으로 등록하고, 프로젝트별 `.code-workspace` 파일을 만들어 폴더·설정·확장 활성화를 묶습니다. 작업 전환 시 정신적 부담이 크게 줄어듭니다.

> **팁:** 프로필 기능으로 언어별 확장 세트를 분리하면 시작 속도가 빨라집니다.

## 역할별 추천 확장

| 역할 | 추천 확장 | 핵심 이유 |
| --- | --- | --- |
| Git 이력 확인 | GitLens | 줄 단위 작성자·커밋 즉시 표시 |
| 오류 가시성 | Error Lens | 문제 패널을 열지 않아도 됨 |
| 원격 작업 | Remote - SSH | 서버 환경을 로컬처럼 사용 |
| API 테스트 | REST Client | `.http` 파일로 요청 버전 관리 |

## 실전 프로 팁

- `code .`로 폴더를 여는 습관을 들이면 파일 탐색기를 거의 열지 않게 됩니다.
- 설정 동기화를 켜면 새 기기 세팅이 5분으로 줄어듭니다.
- 확장 시작 시간은 `Developer: Startup Performance` 명령으로 확인할 수 있습니다.

## 한 걸음 더 — 프로필과 작업 영역으로 환경 분리하기

VS Code의 프로필 기능은 확장 과잉 문제를 구조적으로 해결합니다. 언어나 업무 성격별로 프로필을 만들면 해당 프로필에서만 필요한 확장이 활성화되어 시작 속도와 메모리 사용이 함께 개선됩니다. 예를 들어 문서 작성 프로필에는 마크다운 관련 확장만, 백엔드 프로필에는 디버거와 데이터베이스 도구만 두는 식입니다. 프로필은 내보내기 링크로 공유할 수 있어 팀 온보딩에도 쓸 수 있습니다.

작업 영역 설정(`.vscode/settings.json`)은 프로젝트별 규칙을 강제하는 자리입니다. 들여쓰기, 포맷터, 제외 폴더, 권장 확장을 여기에 적어 저장소에 커밋하면 새로 합류한 사람이 별도 설정 없이 동일한 결과물을 만듭니다. 개인 취향은 사용자 설정에, 프로젝트 규칙은 작업 영역 설정에 두는 경계만 지키면 설정 충돌로 낭비하는 시간이 사라집니다.

마지막으로 확장 신뢰성도 확인 대상입니다. 확장은 로컬 파일에 접근할 수 있으므로 게시자와 다운로드 수, 최근 업데이트 일자를 확인하는 습관이 필요합니다. 오랫동안 업데이트가 없는 확장은 보안 문제뿐 아니라 새 버전에서 동작이 깨지는 원인이 됩니다. 대안이 있다면 활발히 유지되는 쪽으로 옮기고, 사내 코드가 있는 저장소에서는 확장 목록을 팀과 공유해 검토하세요.

## 자주 겪는 문제와 해결법

### Q. 에디터가 갑자기 느려졌습니다.

**A.** `Help → Toggle Developer Tools` 또는 확장 이등분 검색(`Extension Bisect`)으로 원인 확장을 찾을 수 있습니다. 대개 파일 감시 범위가 넓은 확장이 원인입니다.

### Q. 포맷터가 저장할 때마다 다르게 동작합니다.

**A.** 기본 포맷터가 언어별로 다르게 지정된 경우입니다. `editor.defaultFormatter`를 언어별 설정에 명시하고 프로젝트에 설정 파일을 커밋하세요.

### Q. 대용량 파일에서 멈춥니다.

**A.** `files.maxMemoryForLargeFilesMB` 값을 올리거나, 로그 파일은 별도 뷰어로 여는 편이 낫습니다. 구문 강조가 가장 큰 부하입니다.
