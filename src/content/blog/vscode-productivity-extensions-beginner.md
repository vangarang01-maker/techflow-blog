마이크로소프트의 거창한 VS Code 릴리즈 노트와 각종 마케팅 문구를 걷어내고 나면, 실제 매일 일하는 실무자에게 진짜 쓸모 있는 변화는 생각보다 단순합니다. 얼마 전 팀에 합류한 신입 개발자가 제 자리를 찾아와 SOS를 요청했습니다. "선배님, 파일 하나 열 때마다 에디터가 5초씩 멈추고 팬 소리가 너무 크게 납니다." 화면을 확인해 보니, 탐색기 인기 순위에 있는 확장 프로그램 35개가 무분별하게 깔려 있었습니다.

10년 동안 수많은 팀의 개발 및 작업 환경을 튜닝하면서 깨달은 진리는 명확합니다. 확장을 많이 깔수록 에디터는 느려지고, 충돌이 났을 때 원인을 찾느라 버리는 시간만 늘어납니다. 실제 업무에서 6개월 이상 살아남은 확장 프로그램은 딱 10개 남짓이었습니다. 과장된 홍보 문구 대신, 실제 업무 시간을 즉시 줄여주고 실수를 방지해 주는 실전 설정값과 필수 확장 조합을 정리해 드립니다.

---

## 1. 확장을 무분별하게 깔면 안 되는 이유

개발 및 문서 작업 환경에서 에디터는 하루 8시간 이상 사용하는 핵심 도구입니다. 입력 지연 시간이 0.1초만 생겨도 작업자의 몰입 흐름이 깨지게 됩니다.

* **반응 속도 최적화**: 에디터 시작 시간이 1.2초에서 4.5초로 늘어나면 업무 흐름이 자주 끊깁니다.
* **메모리 과점유 방지**: 검증되지 않은 확장 10개만 추가되어도 백그라운드 메모리 점유율이 500MB 이상 급증합니다.
* **충돌 원인 추적**: 포맷터(Formatter)나 린터(Linter) 확장이 꼬이면 저장할 때마다 코드 스타일이 깨져 불필요한 Git 변경 이력이 남습니다.

> 💡 **사전 준비 사항**
> 1. VS Code 최신 버전 설치 및 계정 동기화(GitHub/Microsoft) 활성화
> 2. 현재 설치된 확장 목록 확인: 터미널에서 `code --list-extensions` 입력
> 3. 주로 사용하는 핵심 언어 1～2개 파악

## 2. 확장 설치 전, 기본 설정(Settings)부터 튜닝하기

확장을 여러 개 설치하는 것보다, 기본 제공 설정 3개를 바꾸는 것이 체감 속도 향상에 훨씬 효과적입니다. 마우스로 설정 메뉴를 하나씩 찾는 대신 `settings.json` 파일을 직접 열어 편집해 보세요.

> 💡 **팁**: `Cmd + Shift + P`(macOS) 또는 `Ctrl + Shift + P`(Windows)를 누른 뒤 `Preferences: Open User Settings (JSON)`을 입력하면 환경 설정 파일이 바로 열립니다.

```json
{
  "files.autoSave": "onFocusChange",
  "editor.formatOnSave": true,
  "editor.stickyScroll.enabled": true
}
```

* **`files.autoSave`: "onFocusChange"**: 에디터 창을 벗어나거나 다른 탭으로 이동할 때 자동으로 저장됩니다. `Cmd+S`를 누르는 손가락 피로도를 줄이고, 저장하지 않아 발생하는 실수를 방지합니다.
* **`editor.formatOnSave`: true**: 저장 시 정해진 규칙대로 코드를 자동 정렬합니다. 띄어쓰기나 줄바꿈으로 인한 코드 리뷰 시간을 절약합니다.
* **`editor.stickyScroll.enabled`: true**: 스크롤을 내려도 현재 위치한 함수나 클래스 이름이 상단에 고정됩니다. 긴 코드를 읽을 때 문맥을 놓치지 않게 돕는 핵심 기능입니다.

### 마우스 사용을 절반으로 줄이는 필수 단축키
* **`Cmd/Ctrl + P`**: 파일명 검색 후 즉시 이동 (파일명 뒤에 `@`를 붙이면 함수/심볼 이동, `:`를 붙이면 특정 줄 번호로 이동)
* **`Cmd/Ctrl + Shift + F`**: 프로젝트 전체 단어 검색 및 교체
* **`F12`**: 함수나 변수가 정의된 원본 위치로 즉시 이동
* **`Cmd/Ctrl + D`**: 현재 선택한 단어와 동일한 단어를 하나씩 추가 선택(멀티 커서)

## 3. 역할별 필수 확장 프로그램 10선과 비교

동일한 역할을 하는 확장을 중복 설치하면 성능 저하와 충돌이 발생합니다. 각 영역별로 가장 검증된 1개의 확장만 남겨두는 것이 원칙입니다.

### 역할별 핵심 추천 확장

| 역할 | 추천 확장 | 핵심 이유 |
| :--- | :--- | :--- |
| **Git 이력 확인** | GitLens | 코드 줄마다 마지막 수정자와 커밋 메시지 즉시 표시 |
| **오류 가시성** | Error Lens | 문제 패널을 열지 않아도 에디터 줄 위에 경고문 직접 출력 |
| **원격 개발** | Remote - SSH | 서버 환경에 직접 접속하여 로컬 에디터처럼 작업 |
| **API 테스트** | REST Client | Postman 없이 `.http` 파일로 API 요청 작성 및 버전 관리 |
| **코드 정렬** | Prettier | 언어별 구문 포맷팅 표준화 |
| **태그 자동 완성** | Auto Rename Tag | HTML/XML 태그 수정 시 쌍이 되는 태그 자동 변경 |
| **코드 가독성** | Indent Rainbow | 들여쓰기 단계별 색상 하이라이트 |
| **내비게이션** | Bookmarks | 주요 코드 위치를 북마크하여 빠르게 이동 |
| **문서 작성** | Markdown All in One | 마크다운 목차 자동 생성 및 실시간 미리보기 |
| **환경 분리** | Project Manager | 여러 프로젝트 폴더를 단축키 하나로 전환 |

> 💡 **팁**: 팀원들과 프로젝트 환경을 동일하게 맞추고 싶다면, 프로젝트 최상단 폴더에 `.vscode/extensions.json` 파일을 만들고 아래와 같이 권장 확장 ID를 명시하세요. 프로젝트를 열 때 설치 안내 팝업이 뜹니다.

```json
{
  "recommendations": [
    "eamodio.gitlens",
    "usernamehw.errorlens",
    "esbenp.prettier-vscode"
  ]
}
```

## 4. 스니펫과 작업 영역 정리하기

반복적으로 작성하는 구문이나 설정은 사용자 스니펫(User Snippets)과 작업 영역(Workspace)을 활용해 자동화할 수 있습니다.

### 사용자 스니펫 등록법
`Cmd/Ctrl + Shift + P` -> `Snippets: Configure User Snippets` 선택 후 대상 언어를 지정합니다. 매번 작성하는 기본 템플릿을 등록해 두면 입력 시간이 단축됩니다.

### 작업 영역 파일(`.code-workspace`) 활용
여러 폴더를 동시에 열어 작업할 때, 별도의 작업 영역 파일을 생성하면 폴더 구조, 전용 설정, 활성화할 확장을 하나로 묶어 관리할 수 있습니다. 백엔드와 프론트엔드 폴더를 하나의 창에서 관리할 때 유용합니다.

> 💡 **팁**: 터미널에서 `code .`을 입력해 현재 디렉토리를 열면, 파일 탐색기에서 폴더를 찾는 시간을 절약할 수 있습니다.

## 5. 한 걸음 더 — 프로필과 작업 영역으로 환경 분리하기

VS Code의 **프로필(Profiles)** 기능은 확장 과잉으로 인한 성능 문제를 해결해 주는 기능입니다. 업무 성격에 따라 독립된 환경을 만들 수 있습니다.

* **프로필 세분화**: '마크다운 문서 작성용', '파이썬 개발용', '웹 프론트엔드용'으로 프로필을 분리하세요. 문서 작성 프로필에는 마크다운 관련 확장만 활성화하여 부팅 속도를 단축하고 메모리를 절약할 수 있습니다.
* **프로젝트 설정 강제(`.vscode/settings.json`)**: 개인이 설정한 사용자 설정보다 프로젝트 폴더 내 `.vscode/settings.json` 설정이 우선 적용됩니다. 팀 차원의 탭 간격(Indent Size)이나 린트 규칙을 강제할 수 있어 코드 충돌이 사라집니다.
* **확장 프로그램 보안성 검증**: 확장은 사용자 컴퓨터의 로컬 파일 시스템에 접근할 수 있습니다. 다운로드 수, 마켓플레이스 평가, 마지막 업데이트 일자를 체크하세요. 최근 1년 이상 업데이트가 없는 확장은 보안 위험성이 높으므로 대체제를 찾는 것이 안전합니다.

## 6. 자주 묻는 질문 (FAQ)

**Q1. 에디터 반응 속도가 갑자기 너무 느려졌습니다. 어떻게 원인을 찾나요?**
> `Cmd/Ctrl + Shift + P`를 누르고 `Developer: Startup Performance`를 실행하면 에디터 부팅 시 각 확장이 소비한 시간이 밀리초(ms) 단위로 표시됩니다. 또는 `Help → Toggle Developer Tools`를 열어 CPU 점유율을 확인하거나, `Extension Bisect` 기능을 실행하여 범인 확장을 단계별로 탐색할 수 있습니다.

**Q2. 파일을 저장할 때 포맷터가 제대로 작동하지 않거나 꼬입니다.**
> 여러 개의 포맷터 확장이 충돌하는 경우입니다. `settings.json` 파일에 특정 언어별 기본 포맷터를 명시해 주어야 합니다. 예를 들어 TypeScript 환경에서는 `"editor.defaultFormatter": "esbenp.prettier-vscode"` 설정을 명확히 추가하면 문제가 해결됩니다.

**Q3. 대용량 로그 파일이나 대형 코드를 열 때 VS Code가 멈춥니다.**
> VS Code는 기본적으로 대용량 파일 열기 시 구문 강조(Syntax Highlighting)를 처리하느라 부하가 발생합니다. `settings.json`에 `"files.maxMemoryForLargeFilesMB": 4096` 설정을 추가해 메모리 할당량을 늘리거나, 대용량 로그 파일은 glogg나 Dedicated Log Viewer 같은 전용 뷰어를 사용하는 것을 권장합니다.
